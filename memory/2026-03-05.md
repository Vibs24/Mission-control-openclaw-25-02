## Mission Control PM node stall RCA + fix
- Root cause: PM active-run detection keyed by `agent+attempt` misclassified live retries as inactive when transient retries reused same attempt number.
- Impact: orphan/stale recovery could redispatch while prior run lifecycle was still active, causing backend session-lock/timeouts and retry-budget exhaustion.
- Fix: switched active-run detection to latest lifecycle-status ordering, added transient dispatch cooldown retry (no hard block/no retry budget burn), and gated PM redispatch during cooldown windows.
- Runtime: pushed Convex functions and restarted `ai.missioncontrol.bot`.

## PM reviewer rework routing fix
- Root cause: In `chief_pm_parallel` mode, reviewer `changes_requested` blocked only the reviewer node and returned. No automatic specialist rework routing occurred, so tasks could remain blocked and reviewer never re-ran.
- Fix: Added automatic PM rework router that selects a specialist node, reopens specialist rework, resets reviewer for dependency-aware revalidation, and moves task back to `in_progress` with updated next action.
- Added watchdog fallback: when a blocked reviewer node has `review_changes_requested`, chief now routes rework instead of blindly retrying reviewer.
